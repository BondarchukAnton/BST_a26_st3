# Agent_Task: Автономная миссия «Дрон + Ровер»

## Сценарий миссии (пошагово)

### Этап 1 — Поиск объекта интереса дроном

1. **Взлёт.** Дрон выполняет автономный взлёт (`auto_arm=True`) и набирает рабочую высоту. Навигация — по ArUco-маркерам на полу.

2. **Патрулирование по 3 точкам.** Дрон последовательно облетает 3 заданные точки (координаты — константы в `config/settings.py`).

3. **Поиск объекта интереса (YOLO, 1 класс).** В каждой точке дрон с помощью YOLO-модели ищет на кадре с камеры объект интереса (ровно 1 класс).

4. **Циклический облёт.**
   - Первый проход: дрон летит по точным координатам (как заданы в константах).
   - Последующие проходы: к координатам каждой точки добавляется **случайное отклонение** (величина отклонения — константа в настройках). Это нужно, чтобы охватить большую площадь и повысить шанс обнаружения.
   - Цикл повторяется до тех пор, пока объект не будет найден.

5. **Фиксация находки.** Как только YOLO обнаруживает объект интереса:
   - Дрон зависает **точно над** найденным объектом (корректирует позицию так, чтобы объект оказался в центре кадра).
   - **Координаты объекта фиксируются** — записываются в переменную и/или файл (для последующей передачи роверу).

6. **VLM-анализ.** С позиции над объектом делается снимок с камеры. Снимок отправляется на VLM-модель с промтом (промт задаётся в `config/prompts.py`). Результат анализа VLM (JSON) фиксируется.

7. **Сохранение.** Снимок с объекта сохраняется в `logs/` с меткой времени. Результат VLM также логируется.

8. **Конец Этапа 1.**

---

### Этап 2 — Поиск ровера и передача управления

1. **Полёт к стартовой позиции ровера.** Дрон летит к заранее известной стартовой позиции ровера (координаты — константа в `config/settings.py`).

2. **Обнаружение ArUco-маркера ровера.** На ровере закреплён ArUco-маркер с заданным ID (константа). Дрон сканирует камерой пространство под собой и ищет маркер с этим ID.

3. **Зависание над ровером.** Как только маркер ровера обнаружен, дрон корректирует позицию и зависает точно над ним.

4. **Команда старта роверу.** Когда дрон стабильно висит над ровером, координатор миссии отправляет роверу команду **начать движение** (команда `goal-cell` с координатами объекта интереса, полученными на Этапе 1).

5. **Конец Этапа 2.**

---

### Этап 3 — Движение ровера к объекту интереса

1. **Ровер едет к объекту интереса.** Ровер получает координаты (из Этапа 1) и движется к ним, объезжая препятствия (SLAM + Nav2).

2. **Дрон следует за ровером.** Всё время движения ровера дрон отслеживает ArUco-маркер ровера и следует за ним, удерживая позицию над ровером.

3. **Прибытие к точке.** Ровер достигает координат объекта интереса и останавливается.

4. **Съёмка и VLM-анализ на месте.** Ровер делает снимок front-камерой и отправляет его на VLM.

5. **Цикл VLM-анализа ровера:**
   - Если VLM возвращает `false` — ровер **поворачивается** (на заданный угол или в течение заданного времени), снова делает снимок, снова отправляет на VLM. Цикл повторяется.
   - Если VLM возвращает `true` — ровер извлекает из ответа VLM **координаты финиша** и переходит к Этапу 4.

6. **Конец Этапа 3.**

---

### Этап 4 — Движение ровера к финишу (с уклонением от вражеского маркера)

1. **Ровер движется к финишу.** Получив координаты финиша от VLM, ровер начинает движение к финишной точке, объезжая препятствия.

2. **Дрон продолжает следовать за ровером** и одновременно **ищет вражеский ArUco-маркер** (ID задан константой).

3. **Обнаружение вражеского маркера дроном:**
   - Как только дрон детектирует вражеский маркер в кадре, он определяет **сектор кадра**, в котором находится маркер. Определяется 9 направлений: `center`, `left`, `right`, `up`, `down`, `up-left`, `up-right`, `down-left`, `down-right`.
   - Дрон отправляет роверу сигнал **«ТРЕВОГА»** + **направление** детектированного маркера.

4. **Реакция ровера на тревогу:**
   - Ровер начинает движение в **противоположном** направлении от детектированного маркера.
   - **Важное правило уклонения:** ровер должен двигаться не строго назад, а со смещением:
     - Либо в сторону **финиша** (приоритет продвижения по маршруту).
     - Либо в сторону **откуда он приехал** (если финиш недостижим в данный момент).
   - **Если вражеский маркер детектирован спереди (`up`, `up-left`, `up-right`)**, ровер движется **задним ходом** (реверс). Это критично, потому что разворот ровера занимает много времени, а нужно как можно быстрее отдалиться от маркера.

5. **Потеря ровера дроном (слепая зона):**
   - Если ровер заезжает в зону, где дрон его не видит (например, под навес или в слепую зону лабиринта), дрон фиксирует потерю ArUco-маркера ровера.
   - Ровер должен **регулярно сообщать свои текущие координаты** координатору.
   - При потере маркера дрон летит к последним известным координатам ровера.

6. **Достижение финиша.** Ровер доезжает до финишной точки. Миссия завершена.

## Роли компонентов

| Компонент | Ответственность |
|---|---|
| **Дрон** | Полёт, YOLO-поиск, VLM-анализ (с воздуха), отслеживание ArUco (ровер + враг), LED-индикация |
| **Ровер** | Движение по координатам (Nav2), съёмка front-камерой, VLM-анализ (с земли), уклонение от врага |
| **Координатор** | Оркестрация этапов, передача данных между дроном и ровером, логирование |

---

## Протокол обмена данными

```
Координатор (ноутбук)
    │
    ├── SSH ──► Дрон
    │   Получает: телеметрия, координаты объекта, факт обнаружения,
    │             позиция вражеского маркера, направление врага
    │   Отправляет: команды полёта (куда лететь), параметры поиска
    │
    └── HTTP ──► Ровер
        Получает:  координаты ровера, статус VLM-анализа
        Отправляет: goal-cell, clear, stop, команды уклонения
```

## Ключевые константы (config/settings.py)

| Параметр | Назначение |
|---|---|
| `DRONE_IP`, `DRONE_USER`, `DRONE_PASSWORD` | SSH-подключение к дрону |
| `ROVER_IP`, `ROVER_API_URL` | HTTP API ровера |
| `WAYPOINTS` | 3 точки патрулирования дрона |
| `RANDOM_OFFSET` | Максимальное случайное смещение (м) при повторных проходах |
| `ROVER_START_POSITION` | Стартовая позиция ровера (координаты на поле) |
| `ROVER_ARUCO_ID` | ID ArUco-маркера на ровере |
| `ENEMY_ARUCO_ID` | ID ArUco-маркера врага |
| `VLM_API_KEY`, `VLM_API_BASE`, `VLM_MODEL` | Параметры VLM API |
| `ROVER_ROTATION_ANGLE` / `ROVER_ROTATION_TIME` | Шаг поворота ровера при VLM-анализе |
| `YOLO_MODEL_PATH`, `YOLO_CLASS_ID` | YOLO-модель и класс для поиска |
| `ALTITUDE` | Рабочая высота дрона |

## Последовательность взаимодействия (sequence summary)

```
ЭТАП 1: ПОИСК ОБЪЕКТА
  Drone: взлёт → [цикл: полёт к точке → YOLO-поиск → нет находки → след. точка → 
         случайное смещение → повтор] → YOLO нашёл!
  Drone: зависание над объектом → фото → VLM-анализ → сохранение координат + логов

ЭТАП 2: ПОИСК РОВЕРА
  Drone: полёт к стартовой позиции ровера
  Drone: [цикл: поиск ArUco-маркера ровера → коррекция позиции] → завис над ровером
  Coordinator: отправка команды старта роверу (координаты объекта)

ЭТАП 3: РОВЕР К ОБЪЕКТУ
  Rover: движение к координатам объекта (Nav2)
  Drone: следование за ровером
  Rover: прибыл → [цикл: фото → VLM → false? → поворот → повтор] → VLM вернул true
  Rover: извлёк координаты финиша из ответа VLM

ЭТАП 4: РОВЕР К ФИНИШУ (с уклонением от врага)
  Rover: движение к финишу (Nav2)
  Drone: следование за ровером + поиск вражеского ArUco
  [при обнаружении врага]:
    Drone → alert + направление → Coordinator → Rover
    Rover → движение в противоположную сторону (реверс если враг спереди),
             со смещением к финишу или обратно по маршруту
  Rover: достиг финиша → МИССИЯ ЗАВЕРШЕНА
```

## Особые ситуации (edge cases)

1. **YOLO не находит объект** — бесконечный цикл с нарастающим случайным смещением? Или ограничение по времени/попыткам? (Уточнить.)
2. **VLM возвращает некорректный JSON** — повторный запрос, fallback.
3. **Дрон теряет ArUco-маркер ровера** — лететь к последним координатам ровера.
4. **Ровер теряет связь** — дрон взлетает выше для расширения обзора, ровер останавливается.
5. **Столкновение с вражеским ровером** — штраф −20 баллов; нужно предусмотреть максимально быстрое уклонение.
6. **Вражеский маркер детектирован, но ровер в тупике** — логика выбора направления отхода (приоритет: не врезаться в стену).
